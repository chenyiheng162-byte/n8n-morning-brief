# n8n-morning-brief

每天早上自动往 Discord 发一条待办简报：今天的日历日程，加上从你丢进文件夹的课程大纲、作业说明、项目计划里
自动提取出来的任务。n8n 不常驻：定时任务把它拉起来跑一次，发完就关。

## 安装（macOS，约 10 分钟）

**最简单的方式：** 打开「终端」（⌘空格，搜「终端」），粘贴下面这一行，按回车：

```bash
curl -fsSL https://raw.githubusercontent.com/chenyiheng162-byte/n8n-morning-brief/main/get.sh | bash
```

它把项目下载到 `~/n8n-morning-brief`，然后自动安装（第一次要下载约 3 GB，需要联网和 5 GB 空闲磁盘），装完在浏览器里打开设置向导。
以后想升级，再运行同一行就行，设置会保留。

**打不开 GitHub 时：** 用安装包（zip）。解压后双击「双击安装.command」。第一次双击时 macOS 会拦下来（因为没有苹果签名），
去「系统设置 → 隐私与安全性」，往下找到这个文件，点「仍要打开」。或者在终端里运行 `bash 解压出来的文件夹/install.sh`。

第一次用的话，先看更简短的 [安装说明.md](安装说明.md)。

需要 Apple 的命令行开发者工具（n8n 的 sqlite3 组件要在本机编译；没有时安装程序会在下载任何东西之前弹出苹果的安装窗口并停下）。

它会依次：下载并校验 Node（写死的 SHA-256）、按锁定版本安装 n8n、导入工作流、装每天的定时任务（默认 08:00），
**中间不问任何问题**；最后在浏览器里打开控制台的**设置向导**：填 Discord Webhook（先只读检查，不发消息）、日历链接（逐个测试）、
AI（自动列出模型）、发送时间，最后一键发一条带 🧪 的测试简报，并给出可复制的定时唤醒命令（要管理员密码，需自己在终端执行）。
密钥只存在本机 `~/.n8n-morning-brief/config.local.env`（权限 600），页面上不会再显示。
`--terminal` 改为在终端里问这些问题（隐藏输入，旧的方式）；`--yes` 从环境变量读取、完全不交互。重复运行是安全的：已装好的部分会跳过，已有的设置会保留。

卸载：`bash ~/n8n-morning-brief/uninstall.sh`（加 `--purge` 还会删除运行目录；你的 `~/n8n-inbox/` 永远不会被删）。

## 每天发生什么

```
07:55  pmset 定时唤醒 Mac（自己执行一次，见下）
08:00  launchd 执行 ~/.n8n-morning-brief/scripts/run-brief.sh
       → 先在 n8n 之外把 PDF/DOCX 转成文字 → 启动 n8n → 等它真正就绪
       → 带令牌请求唯一一次 Webhook → 工作流读日历、读文件、拼简报、发 Discord
       → 写"今天已发送"标记 → 关闭 n8n
08:20 / 08:40 / 09:30  补跑时段：已发送则什么都不做
失败：Discord 报警（每天最多 2 条）+ 本机通知 + 日志
```

- **不会重复发：** 请求发出前先写 `pending-日期`。真正发 Discord 的步骤在发出前再写一个 `attempt` 记录，然后只给出三种结论：送达 / 没送达 / 不知道。没送达才删掉 pending、让后面的时段再试；只要请求可能已经到了 Discord（超时、断线、Discord 5xx、发送之后程序出错或被杀），就**不会**自动重发，只报警一次，由你决定要不要补发。这个步骤 n8n 和直连模式共用同一份代码，只重试明确被拒（429）或根本没连上的情况。
- **不会发旧版本：** Webhook 路径里带整个工作流的哈希，n8n 里是旧版本就根本没有这个路径（404）。路径之外还要带令牌。
- **n8n 起不来时：** 默认改用"直接引擎"（`scripts/brief.mjs`，跑同一份代码，不经过 n8n）发出简报。只有在 n8n 根本没接受请求时才会回退；`BRIEF_FALLBACK=off` 可关闭。
- **睡眠错过 08:00：** launchd 唤醒后补跑；关机则当天漏发，下次简报会补一句"前几天没发出"。
- **日历抓不到：** 用最近一次成功的缓存（48 小时内，标注"缓存"）；没有缓存就写"日程未知"，绝不写成"没有日程"。服务器返回 200 但内容不是日历（登录页、错误页）也算抓取失败，不会覆盖好的缓存。同一个链接写了几遍只读一次。日历里用了却没定义的时区（有些课表系统会省略），按系统的时区数据自动换算；不是标准时区名的会在简报里提示，不会乱猜。

## 怎么用（任务部分）

1. 把课程大纲、作业说明、项目计划等放进 `~/n8n-inbox/`（支持 pdf、docx、txt、md；扫描图片版 PDF 读不出文字）。
2. 下次简报时，AI 抽出任务写进 `~/n8n-inbox/tasks.csv`，状态是「待确认」，简报里会提醒你。
3. 用 Excel 或文本编辑器打开 `tasks.csv`：要做的改成「进行中」，不要的改成「忽略」，做完的改成「完成」。只有「进行中」进简报。
4. 文件里写"第 4 周周五"这类相对日期时，在配置里加 `BRIEF_BASE_DATE=YYYY-MM-DD`（第 1 周周一）。AI 不会猜日期，缺什么会写在备注里。
5. **去重规则很保守：** 只有"课程名（规范化后）、任务名、截止日"三者完全一样才合并；不同课程的同名任务都保留，拿不准的在备注里标"可能重复"。
6. 日期 `2026/10/2`、`2026.10.2` 都认得；「进行中」但没有可识别截止日的任务会单独提示。每次运行第一次改写 `tasks.csv` 前留一份 `tasks.csv.bak`；
   你自己加的列原样保留；表头被改坏时程序**不会**改动文件，并在简报里报错。**别在 Excel 里开着 `tasks.csv` 的时候等早上的运行**（Excel 保存会覆盖程序写入的内容）。
7. 太长的文件分段读（每段默认 24,000 字符，最多 10 段，超出部分不读并每周提醒一次）；一次读不完的文件记住**已读到第几个字符**，下次从那里接着读（中途改了 `BRIEF_CHUNK_CHARS` 也不会漏读或重读）；一段太慢时拆成两半，读完的半段立即保存；小文件优先。
8. 某个文件反复失败：
   ```bash
   ./scripts/inbox.sh status            # 每个文件的状态：新 / 读到一半 / 已处理 / 暂停 / 已放弃
   ./scripts/inbox.sh retry 文件名      # 修好原因后重来（加 --full 从头读）
   ./scripts/inbox.sh ignore 文件名     # 不读了（unignore 取消忽略；remove 移到废纸篓）
   ```
   失败 3 次暂停，之后大约每天再自动试一次（距上次失败满 20 小时），最多再试 3 次，仍失败就放弃并只提醒一次。提取不出文字的 PDF/DOCX 和正在等待提取的文件不占用每次处理 10 个文件的名额。

## 控制台（推荐）

```bash
./scripts/console.sh        # 在浏览器里打开本机控制台（也可以运行运行目录里的同名脚本）
```

一个只在本机打开的网页（配色参照 shadcn/ui 的 zinc 方案，图标用开源的 Lucide，都内嵌在页面里，不需要联网），支持深色模式、手机宽度，按 ⌘K 打开命令面板，数字键 1–6 切换页面：
- **总览**：今天有没有送达、离下一次定时的倒计时、健康检查环、连续送达天数 / 14 天送达率 / 平均送达时间 / 待确认任务四个指标、**接下来的日程和 7 天内的截止**（日程来自上一次运行缓存的日历，不联网）、最近 14 天每天送达时间的柱状图（一眼看出唤醒是否准点）、最近一次运行各阶段耗时。
- **任务**：直接在表里改状态、截止日、名称；新增任务；一键确认全部「待确认」；搜索；下载任务表。保存前会确认任务表没被早上的运行或 Excel 同时改过，并留 `.bak`。
- **收件箱**：拖文件进去；看每个文件读到哪了；查看 AI 将读到的文字；重试、重新读、忽略、**取消忽略**、**移到废纸篓**（不直接删除，可以从废纸篓找回）。
- **设置**：分组填写，保存前逐项校验；密钥和日历链接只显示「已设置」和主机名，页面上永远看不到它们的值；可以测试 AI 连接、测试日历链接。
- **日志**：终端样式，按日期查看，可只看失败或成功，可自动刷新。
- **工具**：预览简报（按 Discord 的样子显示）、发测试简报、补发、完整自检、测试 AI、测试日历、**测试本机通知**、改发送时间、复制定时唤醒命令、关闭控制台。

第三方素材：图标来自 [Lucide](https://lucide.dev)（ISC 许可，版权归 Lucide Icons and Contributors），内嵌在 `scripts/console/index.html` 里。

安全：只监听 127.0.0.1；启动时打印一个带本次启动有效的口令的链接（写成只在本机有效的 HttpOnly Cookie）；拒绝其他主机名的请求（防 DNS 重绑定）；每个修改请求都要带一个普通网页表单无法添加的请求头；操作期间与定时运行共用同一把锁。
关掉终端或按 Ctrl-C 就关闭了，定时发送不受影响。

## 常用命令

```bash
./scripts/status.sh                         # 一屏看健康状况（装了什么、上次运行、待处理问题；有问题退出码为 1）
~/.n8n-morning-brief/scripts/run-brief.sh --dry-run   # 只生成并打印简报：不发送、不调 AI、不写标记、不改任务表（会联网读日历，并更新日历缓存）
~/.n8n-morning-brief/scripts/run-brief.sh --test      # 真发一条带 🧪 的测试简报，不写"已发送"标记
~/.n8n-morning-brief/scripts/run-brief.sh --force     # 今天已发过也再发一次（同样不写标记）
./scripts/install-launchd.sh 08:00          # 同步脚本并安装/更新定时任务
./scripts/uninstall-launchd.sh              # 移除定时任务
./scripts/set-discord-webhook.sh            # 隐藏输入保存 Webhook（不要贴进聊天）；还有 set-ai-key.sh、set-calendar-urls.sh
tail ~/.n8n-morning-brief/logs/run-$(date +%F).log
```

定时唤醒（需要管理员密码，只能自己执行；`pmset repeat` 只保留一条规则，会替换你原来的，先看 `pmset -g sched`）：

```bash
sudo pmset repeat wakeorpoweron MTWRFSU 07:55:00
```

**过夜一定要接电源。** 实测过：Mac 用电池过夜、电量耗尽进入休眠时，定时唤醒不会发生；接上电源醒来后 launchd 立刻补跑，简报晚到但不会丢。

## 设置（`~/.n8n-morning-brief/config.local.env`）

每行 `KEY='值'`。**配置文件不是脚本，不会被执行**，只接受 `KEY='值'`、`KEY="值"`、简单的无引号值，
键名限于 `DISCORD_WEBHOOK_URL`、`ICS_URLS`、`AI_*`、`BRIEF_*`、`N8N_*`、`EXECUTIONS_*`；看不懂的行会被跳过并在 `status.sh` 里列出行号。
无效的取值（比如拼错的时区、`BRIEF_EVENT_DAYS=abc`）会退回默认值，并在简报末尾显示"⚙️ 设置提示"，而不是悄悄失效。

| 设置 | 作用 | 默认 |
|---|---|---|
| `BRIEF_TZ` | 时区 | 系统时区 |
| `BRIEF_EVENT_DAYS` | 往后看几天的日程（1–14） | 3 |
| `BRIEF_VIEW` | `compact` 或 `full`（full 多显示耗时脚注） | compact |
| `BRIEF_IGNORE="Recess\|Lunch"` | 隐藏匹配的日程 | 无 |
| `BRIEF_STRIP="\s*\(Ext\.?\s*\d+\)"` | 去掉标题里的噪音 | 无 |
| `BRIEF_BASE_DATE` | 第 1 周周一，用于"第 N 周" | 无（周一以外会警告） |
| `BRIEF_AUTO_CONFIRM=1` | AI 抽出的任务直接算「进行中」（默认要你确认） | 关 |
| `BRIEF_NOTE` | 简报里附一句固定备注 | 无 |
| `BRIEF_AI_TIMEOUT_MS` | 单次 AI 请求超时（超时会把分段减半再试） | 90000 |
| `BRIEF_FALLBACK=off` | 关闭"n8n 起不来时直接发" | 开 |
| `BRIEF_REUSE_N8N=1` | 允许复用已在运行的 n8n（默认拒绝，避免碰到你别的项目；复用时不会清理它的数据库） | 关 |
| `BRIEF_ENGINE=direct` | 完全不用 n8n，用同一份节点代码直接发（装好 n8n 之后才能这样用） | n8n |
| `N8N_PORT` | n8n 端口（任务执行器用 端口+1） | 5690 |
| `BRIEF_EXEC_KEEP_DAYS` | 失败执行记录保留天数 | 3 |

AI 服务不支持 `response_format` 时会自动关闭并记住；AI 返回夹杂文字的 JSON 也能提取；遇到 429/5xx 会退避重试。

## 目录：源码与运行时分开

macOS 不允许 launchd 拉起的进程读取 `~/Documents`（`Operation not permitted`），所以运行时不能放在这里。

| 位置 | 内容 | git |
|---|---|---|
| 本目录（下载 / 解压的文件夹） | 脚本、工作流源码与生成的 JSON、测试 | 是 |
| `~/.n8n-morning-brief/`（`BRIEF_HOME`） | Node、n8n、数据库、日志、`config.local.env`、脚本副本 | 否 |

- 改了 `scripts/` → `./scripts/install-launchd.sh` 同步。
- 改了 `workflows/src/` → `./scripts/deploy-workflow.sh`（生成 JSON、备份数据库、导入 n8n、修正发布指针、校验；工作流文件和脚本都先放进暂存目录，最后整体改名切换；任何失败都把数据库、工作流和脚本一起回滚）。
- 运行目录里有只由 `install.sh` 创建的标志文件，所有脚本在动它之前先检查，防止误操作别的目录。
- 发布到公开仓库（一行命令从这里下载）：`./scripts/publish.sh`，内容和安装包完全一样，提交用 GitHub 的匿名邮箱。
- 给别人的安装包：`./scripts/make-package.sh` → `dist/n8n-morning-brief-<提交号>.zip`。只打包已提交的文件，不含审核记录；打包前对照本机设置里的真实密钥值、密钥样式、主目录路径、用户名和邮箱扫描一遍，有任何命中就不生成。

## 已知坑

- **重新导入工作流后，n8n 第一次启动会跑旧版本，而且显示"成功"。** 根因：`n8n import:workflow` 会塞一条指向旧版本的待发布事件。
  `deploy-workflow.sh` 在 n8n 停止时改正指针；再加上带哈希的 Webhook 路径，旧版本不可能发出简报。
- **等待分两种：** "就绪等待"只在 404/连接被拒时重复请求；请求一旦被接受只发**一次**，最多等 20 分钟，超时不重试。
- **n8n 不保存成功的执行记录**：它只活几十秒，内置清理等不到触发，否则日程会在数据库里无限累积；`run-brief.sh` 另外按天清理失败记录。
- **PDF/DOCX 解析库在 n8n 沙箱里不能用**，所以文字提取放在 `scripts/extract-inbox.mjs`（启动 n8n 之前）。不要开 `N8N_RUNNERS_INSECURE_MODE`。
- bash：`$VAR` 后面紧跟全角字符会被当成变量名的一部分（`set -u` 下静默退出），一律写 `${VAR}`；`n8n` 输出不要接 `| head -1`；macOS 没有 `timeout`。
- 状态不明后用 `run-brief.sh --force`（或控制台里的「补发」）补发即可；那一天之后不会被说成"漏发"。
- Webhook 地址、日历私人地址、AI 密钥都是密钥：只存在 `config.local.env`，报错信息里的链接会被替换成 `<链接>`。
